# Published版の取得・手動補完

## 何を確認するか

認定書タブの一括確認では「OJ掲載版」と「発行団体の最新Published版」を別々に表示します。EMCではPublished、REDではOJを初期の集計基準にしています。対象指令と集計基準は変更できます。

これは認定スコープに対象版が含まれるかの照合です。Publishedであることは、各市場でその版が適用可能であることを意味しません。OJの制限事項、認定書の条件、米国・カナダ等の指定版や移行期限は別途確認してください。

| 条件 | 表示 |
|---|---|
| スコープに対象版を含む（例: 2012/2013とOJ 2013） | 有効 |
| OJ原文に版数がない | OJ側は有効。情報取得失敗とは区別 |
| スコープが対象版より古い版のみ | 警告 |
| スコープの版数がない | 版情報なし。最新版を適用する認定条件を確認 |
| 本体版は一致するが追補・正誤票が不足 | 注意 |
| 規格名変更・後継関係が未確認 | 注意。同じ番号だけでENとEN IEC等を同一視しない |
| 発行団体が元規格の廃止を明示し、現行Published版がない | 廃止。後継があれば最新版列の中に表示 |
| 最終確認から日数が経過 | 日数だけでは判定を変更しない。最終確認日時を表示 |
| 取得失敗・確認日時の欠落や不正・解釈不能 | 未確認。前回値があれば参考表示 |

複合表記は規格単位に分解します。`EN 301 489-1 / -3` は部番の列挙であり、版数の列挙ではありません。認定原文から規格を特定できない項目も一括結果から消さず、未確認として残します。認定書の有効期限・試験方法の適用範囲自体の判定は別機能です。

## 自動取得範囲

- ETSI: 公開検索のCurrent・Publishedを取得。履歴・撤回・承認中の文書を除外。
- CEN/CENELEC: 公式公開検索のPublished結果。ENからEN IEC等に名称が変わった候補は注意として表示。
- IEC/CISPR: IEC公式Webstoreの公開検索とライフサイクル。PUBLISHEDの本体・追補・正誤票を統合。
- ISED: RSS/ICESの公式一覧から現行文書を辿り、本文ヘッダーのIssueを取得。
- ISO、ANSI/IEEE、JIS、KS、VCCI、FCC系（MP、KDB等）およびその他の資料: 現段階では公式検索へのリンクと手動補完。自動で最新版取得済みとは表示しない。

公開側の構造変更、アクセス制限、不完全な検索結果、規格の特定失敗は未確認にします。ログイン・有料本文・認証回避を利用しません。Webページ更新日や再確認年を規格の版数には流用しません。

## 操作

1. 規格団体公式検索タブ → 「版情報を表示」。発行団体・番号で絞り込みます。
2. 公式情報の取得は週次巡回で行います。画面の単発「再取得」とAPIは廃止しました。初回の確認が終わっていない規格は未確認です。
3. 手動対象は「確認・補完」。公式サイトで最新版・発行状態・追補・正誤票を確認します。
4. 版（`2020`、`V2.2.2`、`Issue 6`、`2020+A1:2024+COR1:2025`等）、状態、公式URL、確認根拠を入力し保存します。本体の年とEdition番号は混同しないでください。
5. 認定書タブで一括確認を再実行します。保存だけでは既に表示した結果を変更しません。

手動値を優先しますが、自動値は別に保持します。「自動取得に戻す」で補完を解除できます。保存・解除の履歴は残ります。根拠メモは利用者が閲覧できるため、顧客機密・個人情報・管理キーを書かないでください。

廃止確認済みの規格は単一版の手動補完・解除では変更できません。廃止・後継関係の修正は保守担当に依頼し、公式根拠を確認して週次巡回と共通の検証手順で反映します。廃止日は不明なら「不明」と表示します。後継がないことを確認した場合と、後継が未確認の場合は区別します。

後継規格は複数・部分置換にも対応します。後継関係に書かれた引用版と、後継規格自身の最新Published版は別々に表示します。元規格の廃止はOJ掲載失効や認定失効を意味せず、後継が自動的に認定範囲へ入ることもありません。「廃止」はPublishedを集計基準にしたときだけ絞り込めます。「版情報なし」は「注意」の隣です。

自動取得・手動補完ともに、日数の経過だけでは未確認に戻しません。台帳と一括照合結果の「最終確認日時」は、保存済みの版情報を最後に確認できた日時です。規格の発行日や一括照合の実行日時とは異なります。取得失敗時は前回値とその最終確認日時を保持し、未確認として参考表示します。

判定は保存済みの版情報との照合結果であり、現在の最新版であることを保証するものではありません。利用時は最終確認日時・公式出典を確認してください。

## 週次巡回と変更通知

定期確認は日曜09:00（日本時間）の外部実行器へ移行し、Workerの15分巡回は停止しました。D1の現行認定スコープから対象を読み込み、公式出典を確認した項目だけ版台帳へ反映します。調査中に他の更新が入った項目は上書きしません。

画面の「定期調査で確認」は週次調査で根拠が得られた情報です。差分がない場合も最終確認日時を更新しますが、版数変更の通知は出しません。取得失敗・解釈不明は以前の版・確認日時を保持し、巡回記録で未確認理由を報告します。調査に失敗しただけで旧版データを消したり、年齢だけで判定をリセットしたりしません。

Published版の本体版・追補・正誤票、廃止状態、後継・置換範囲に変更があった場合は、検知から7日間、全タブ共通のお知らせに規格・変更前後・検知日・公式出典を表示します。閉じる操作はそのブラウザーで有効です。新しい変更を検知したら再表示します。確認日時だけの更新では通知を延長しません。個別の手動編集は週次変更通知には含みません。

ローカルのスケジューラーで運用する場合、実行時にMacとアプリが起動している必要があります。未実行・未確認は完了扱いにしません。保守用の実行仕様とJSON形式はリポジトリの`docs/publisher-review-runbook.md`にあります。

## 管理者の初期設定

既存本番への追加適用は以下の順です。認定スコープの再シードは不要です。

```bash
npm test
npm run db:migrate
npx wrangler secret put CATALOG_ADMIN_TOKEN
npm run deploy
```

管理キーは十分に長いランダム値を使用し、管理者だけに安全に共有します。未設定時は閲覧のみで、書込みAPIは401になります。通常のCloudflare Accessログインだけでは書込みを許可しません。ブラウザーでは管理キーを保存せず、ページを閉じると入力は失われます。入力はHTTPSの運用画面でのみ行ってください。

メール認証を明示的に有効化した環境では、管理キーの代わりに`@sgs.comでログイン`が表示されます。本人のメール受信を一度限りのコードで確認すると編集できます。固定の個人キーは配布しません。編集者のID・メール・日時は非公開の操作記録へ保存され、公開の版履歴には出ません。Accessモードは共有管理キーを受け付けません。切替設定・受信テストは保守担当がリポジトリの`docs/catalog-email-auth.md`に従って行います。

ローカルでは `.dev.vars` にテスト専用の `CATALOG_ADMIN_TOKEN` を設定し、`npm run db:migrate:local` の後に `npm run dev -- --local` を使用します。通常の `npm run dev` は `remote: true` により本番D1につながるため、書込み試験には使用しないでください。

台帳は`publisher_catalog`、`publisher_catalog_history`、`publisher_sync_lock`、週次記録と通知は`publisher_review_runs`、`publisher_review_results`、`publisher_changes`です。認定書の正本MD、PDF、既存スコープ、OJキャッシュとは分離しています。週次処理は更新前後の比較と重複実行防止を行います。既存の単発自動取得のロックは10分で失効します。

公式取得の読取りテスト: `npm run check:publishers`。これはD1に書込みません。
