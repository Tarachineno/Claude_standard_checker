# OJ元データの解析と表示

## 取り込み

- 旧EC形式（規格番号・タイトルが別列）と新EC形式（`Reference and title Provision`）をヘッダー名で識別する。
- 新形式の先頭にある生成日・空行を読み飛ばし、規格番号、タイトル、Noticeを分離する。Notice中の参照規格を独立したOJ掲載として登録しない。
- 版数は規格番号に付記された年・V番号から取得する。OJ掲載日を規格の版年には使わない。
- 追補・正誤票は連続した版トークンのみ解析し、`Article`等の本文を`A`と誤認しない。`AC:YYYY-MM`は正誤票として月まで保持する。
- `+A1:2020`を移動・分断しない。別行で列挙された同一本体版の追補は併合する。
- 掲載開始日・掲載終了日は実際の対応列から取得し、`DD.MM.YYYY`もISO日付に変換する。未知の列形式や不正な適用日を黙って有効扱いしない。

## 表示

`OJ有効版数`列では、`EN 302 065-2 V2.1.1`のように版を含む名称を先頭に表示する。併存する有効版がある場合は全て表示する。

「版情報なし」は**認定スコープ側に版の指定がない**判定であり、OJ版が不明という意味ではない。比較対象と判定理由を併記する。OJ側が本当に版指定なしの場合は、従来どおりスコープの版を問わず有効とする。

更新日の取得優先順位は次のとおり。

1. XLSX内の`Generated …`に記載された生成日
2. XLSX内の`ModifiedDate`プロパティ
3. 実際に取得した元データのHTTP `Last-Modified`
4. 全て不明なら「不明」

APIでは`source_updated_at`と`source_updated_kind`を追加し、取得確認日時`last_checked`とは区別する。ファイル内の日時とHTTP日時はUTCの日付を表示し、その旨をラベルに明示する。以前の取得時刻由来の`last_modified`は代用しない。KV・同梱XLSXでもファイル自身の更新日を読み取る。

## 全件CSV出力

比較結果の「全件CSVをエクスポート」は、認定・施設・検索・判定の絞り込みと表示中のOJ指令を無視し、`/api/scope-oj-version-check?directive=ALL`から全件を取得する。画面の結果や選択条件は変更しない。

1スコープを1行とし、複数規格・指令はセル内の改行でまとめる。スコープ、OJ版、Published版、判定理由、更新・確認日時、出典、廃止・後継情報、認可書PDF・詳細リンクを33列に出力する。対象は現行の比較情報であり、旧認可書や台帳の全変更履歴ではない。

UTF-8 BOM付きCSVでExcelの日本語読込みに対応する。改行・引用符をエスケープし、数式に見えるセルを文字列化する。認証情報・管理キー・非公開の編集者情報は含めない。取得失敗・不完全な応答では出力せず再試行可能にする。未確認や出典取得エラーの行も省略せず、その判定理由とともに保持する。
